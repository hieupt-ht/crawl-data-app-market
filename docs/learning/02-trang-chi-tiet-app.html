Trang chi tiết app và “URL là trạng thái”

Hôm nay mình chuyển phần chi tiết app từ panel nổi bên phải sang một trang riêng. Để quay lại Overview không bị mất bộ lọc, mình đưa trạng thái xem lên URL. Trong lúc làm còn bắt được một lỗi kinh điển của React: stale closure.

1. Hôm nay làm gì

  • Thêm trang /apps/[appId]. Ở bảng ⑤ “App đối thủ”, bấm một app là chuyển sang trang này thay vì mở panel.
  • Trang app có 5 khu vực: ① so sánh pain point với trung bình lĩnh vực, ② mong muốn, ③ xu hướng theo tháng, ④ đọc review (lọc, tìm, phân trang), ⑤ app cùng lĩnh vực.
  • Bộ lọc, lĩnh vực đang chọn và trọng số giờ nằm trên URL, ví dụ /?months=6&domain=pdf&w=60-35-25. Nhờ vậy F5, gửi link hay bấm “← Overview” đều giữ nguyên màn hình.
  • Panel khi bấm ô heatmap vẫn giữ dạng nổi bên phải, vì ở đó chỉ cần đọc lướt.
cd frontend
npm run dev
# mở http://localhost:3000 → bấm một app ở bảng ⑤
# hoặc mở thẳng http://localhost:3000/apps/com.apero.pdfreader?months=6

3. Kiến thức chính

3.1 Dynamic route: thư mục [appId]

Trong Next.js, thư mục là đường dẫn. Thư mục tên có ngoặc vuông [appId] là một “ô trống”: URL /apps/com.apero.pdfreader sẽ khớp vào đó, và giá trị "com.apero.pdfreader" được truyền vào qua prop params. Ở Next 16, params là một Promise, nên phải await.

src/app/apps/[appId]/page.tsx

export function generateStaticParams() {          // dựng sẵn 40 trang lúc build
  return getDashboardData().apps.map((app) => ({ appId: app.id }));
}

export default async function AppPage({ params }: PageProps<"/apps/[appId]">) {
  const { appId } = await params;
  const app = getLookups().appById.get(decodeURIComponent(appId));
  if (!app) notFound();                             // id sai -> giao diện 404
  return <Suspense fallback={<PageLoading />}><AppDetail app={app} /></Suspense>;
}

Lỗi hay gặp: viết params.appId mà không await, cách của Next 14 trở về trước. Ở Next 15/16, TypeScript sẽ báo lỗi. PageProps là kiểu do Next tự sinh: chạy npx next typegen (hoặc npm run dev) nếu editor báo không tìm thấy.

3.2 URL là trạng thái (state)

Bài 01 giữ bộ lọc bằng useState, nên chuyển trang là mất. Lần này mình đặt chúng lên URL. URL giống “tờ ghi chú dán trên địa chỉ trang”: ai mở link cũng thấy đúng những gì bạn đang xem.

src/lib/viewState.ts

// Đọc: URL -> object. Giá trị sai thì dùng mặc định, không bao giờ làm trang lỗi
export function parseViewState(params: ReadableParams): ViewState {
  const monthsParam = Number(params.get("months"));
  const months = VALID_MONTHS.includes(monthsParam as MonthsRange) ? ... : DEFAULT_FILTERS.months;
  ...
}

// Ghi: object -> "?months=6&domain=pdf". Giá trị bằng mặc định thì bỏ qua cho gọn
export function buildQuery(view: ViewState): string { ... }

Cặp hàm parse / build này là mẫu rất phổ biến. Một hàm đọc thì chịu được dữ liệu bẩn (ví dụ người dùng gõ ?months=99), một hàm ghi thì luôn tạo ra dữ liệu sạch.

Lỗi hay gặp: tin tưởng dữ liệu từ URL. Ai cũng sửa được URL, nên luôn kiểm tra và có giá trị mặc định.

3.3 useSearchParams phải nằm trong <Suspense>

Lúc build, Next.js dựng sẵn HTML nhưng chưa biết URL thật sẽ có ?months= bao nhiêu. Vì vậy component nào đọc URL bằng useSearchParams() phải bọc trong <Suspense fallback={...}>. HTML ban đầu chỉ hiện phần fallback (“Đang tải dữ liệu…”), rồi trình duyệt vẽ phần thật sau khi đọc được URL.

src/app/page.tsx

export default function Home() {
  return (
    <Suspense fallback={<PageLoading />}>
      <Dashboard />          {/* bên trong gọi useSearchParams() */}
    </Suspense>
  );
}

Lỗi hay gặp: quên Suspense thì npm run build báo lỗi “useSearchParams() should be wrapped in a suspense boundary”.

3.4 Stale closure: lỗi “bấm nhanh bị mất lựa chọn”

Đây là lỗi mình gặp thật trong lúc kiểm tra. Ban đầu code viết như sau:

// ❌ Phiên bản đầu
const updateView = (patch) => writeToUrl({ ...view, ...patch });   // dùng biến `view` của lần render này

Mỗi lần React render, hàm updateView “chụp ảnh” biến view lúc đó (gọi là closure, bao đóng). Bấm 2 nút thật nhanh, trước khi React kịp vẽ lại, thì sẽ xảy ra chuyện sau:

Bấm “6 tháng”: ghi {months: 6} lên URL ✔

Bấm “Đọc PDF” (React chưa vẽ lại): dùng ảnh chụp cũ {months: 12} + {domain: pdf}

Kéo thanh trượt: dùng ảnh chụp lúc có months=6 nhưng chưa có domain → ghi đè, mất domain ✘

Cách sửa: mỗi lần cập nhật thì đọc trạng thái mới nhất ngay từ URL, không dùng ảnh chụp cũ.

src/lib/viewState.ts

export function updateViewInUrl(patch: Partial<ViewState>): void {
  const current = parseViewState(new URLSearchParams(window.location.search)); // luôn mới nhất
  const url = `${window.location.pathname}${buildQuery({ ...current, ...patch })}`;
  window.history.replaceState(null, "", url);
}

Với useState, cách tương tự là dùng dạng hàm: setCount(c => c + 1) thay vì setCount(count + 1). Hàm toggleDomain trong Dashboard của bài 01 đã viết theo đúng kiểu này.

Lỗi hay gặp: thử bằng tay thì không thấy lỗi, vì người bấm chậm. Lỗi chỉ lộ ra khi máy bấm (test tự động) hoặc khi mạng chậm. Đây là lý do nên viết test tự động.

3.5 replaceState vs pushState vs <Link>

CáchDùng khiTrong dự án
<Link href>Chuyển sang trang khácTên app ở bảng ⑤, “← Overview”, app cùng lĩnh vực
router.push()Chuyển trang từ code (không phải thẻ <a>)Bấm chỗ trống trong dòng bảng ⑤
history.replaceStateĐổi URL cùng trang, không thêm vào nút BackBộ lọc, thanh trượt
history.pushStateĐổi URL cùng trang và muốn Back quay lại được(chưa dùng)

Thanh trượt dùng replace vì kéo một lần có thể tạo ra 20 lần đổi giá trị. Nếu dùng push, người dùng phải bấm Back 20 lần.

src/components/dashboard/CompetitorTable.tsx

<tr onClick={() => onOpenApp(app.id)}>          {/* bấm cả dòng */}
  <Link href={appHref(app.id)}
        onClick={(event) => event.stopPropagation()}>  {/* tránh chạy 2 lần */}
    {app.title}
  </Link>

Lỗi hay gặp: không có stopPropagation() thì bấm vào Link sẽ kích hoạt cả onClick của <tr> chứa nó (sự kiện “nổi bọt” lên cha), dẫn tới điều hướng 2 lần.

3.6 Component “được điều khiển” (controlled) và đặt lại trang 1

ReviewExplorer không tự giữ state. Bộ lọc và số trang do cha AppDetail giữ. Lý do: khi bấm một dòng ở khu “So sánh pain point” (một component khác), cha phải đổi được bộ lọc của khu review.

src/components/app-detail/AppDetail.tsx

const changeReviewQuery = useCallback((query: ReviewQuery) => {
  setReviewQuery(query);
  setReviewPage(1);           // đổi bộ lọc thì quay về trang 1
}, []);

const showReviewsForPain = (painId: string) => {
  changeReviewQuery({ ...reviewQuery, painId });
  reviewSectionRef.current?.scrollIntoView({ behavior: "smooth" });
};

Lỗi hay gặp: đang ở trang 5, lọc lại chỉ còn 2 trang, thế là màn hình trống. Có 2 lớp bảo vệ: đặt lại trang 1 khi đổi bộ lọc, và trong ReviewExplorer dùng Math.min(page, pageCount).

3.7 So sánh với “mặt bằng”: điểm phần trăm

Nói “app này có 30% review chê crash” thì chưa biết là nhiều hay ít. Phải đặt cạnh mức chung của lĩnh vực (23%) mới thấy app này nặng hơn. Hiệu 30% − 23% = 7 điểm phần trăm (percentage points). Đây là cách nói chính xác, khác với “nhiều hơn 7%” (vì 30 lớn hơn 23 khoảng 30%).

src/components/app-detail/PainComparison.tsx

const NOTABLE_GAP = 0.05;   // chênh từ 5 điểm trở lên mới coi là khác biệt rõ

if (gap >= NOTABLE_GAP)  → "+7 điểm · nặng hơn"   (màu nhấn: điểm yếu riêng = cơ hội)
if (gap <= -NOTABLE_GAP) → "-11 điểm · nhẹ hơn"
otherwise               → "≈ ngang mặt bằng"

Lỗi hay gặp: “trung bình lĩnh vực” mà lại tính theo bộ lọc công ty thì sẽ chỉ so với chính mình. Vì vậy AppDetail lọc review với companyId: "all".

5. Tự kiểm tra

Câu 1. Mở /?months=99&w=abc thì dashboard hiện gì? Vì sao không bị lỗi?

Dashboard hiện 12 tháng và trọng số 40/35/25. Hàm parseViewState chỉ chấp nhận 3/6/12, và parseWeights kiểm tra phải đúng 3 số nguyên 0–100. Sai thì quay về mặc định.

Câu 2. Vì sao kéo thanh trượt dùng replaceState chứ không phải pushState?

Mỗi lần kéo tạo ra nhiều giá trị liên tiếp. Dùng push thì mỗi giá trị thành một mục trong lịch sử, và người dùng phải bấm Back rất nhiều lần mới thoát khỏi trang.

Câu 3. Cho const [count, setCount] = useState(0). Gọi setCount(count + 1) hai lần liên tiếp trong cùng một hàm thì count thành bao nhiêu? Sửa thế nào để ra 2?

Ra 1, vì cả hai lần đều dùng ảnh chụp count = 0 (stale closure). Sửa thành setCount(c => c + 1) hai lần, React sẽ truyền giá trị mới nhất vào c.

Bài tập 4. Đưa trang review hiện tại (reviewPage) lên URL, để gửi link “trang 3 review của app X” cho người khác.

Gợi ý: thêm tham số ?rp=3. Đọc bằng useSearchParams().get("rp") (nhớ kiểm tra là số nguyên ≥ 1), ghi bằng history.replaceState. Thử nghĩ xem tham số này có nên được mang về Overview không. Đáp án: không, nên đừng thêm nó vào ViewState chung.

Bài tập 5. App có 40% review chê quảng cáo, lĩnh vực là 32%. Trang hiện chữ gì? Nếu đổi NOTABLE_GAP thành 0,10 thì sao?

Chênh 8 điểm, lớn hơn hoặc bằng 5, nên hiện “+8 điểm · nặng hơn”. Với ngưỡng 0,10 thì 8 < 10, nên hiện “≈ ngang mặt bằng”.
